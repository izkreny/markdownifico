# Plan: settle markdownifico's scope (#6)

The issue holds the question, the columns and the rules for a cell; this plan says how the cells are gathered, checked and turned into a scope. The deliverable in the repository is `docs/research/features.md` (new). The linter clones, the gathering notes and the table-shape check live in the session's working folder and are thrown away.

## Approach

- **Gathering is fanned out, judging is not.** Reading 23 tools for the same rows is mechanical, so four subagents gather, each on a group of columns, against one row list and one cell legend. The orchestrating session re-reads the cited source of every cell the scope decision rests on, writes the table and makes the scope decision.
- **Every column is read at a named version.** The parsers at the reference tree's clone tags, and the linters at the versions the 2026-09 survey rechecked on 2026-10-23, shallow-cloned at that tag into the session folder; mdl is already in the reference tree.
- **Every cell cites its source**, as a GitHub permalink at the tag, in a sources block per tool below the table. A subagent that finds nothing reports `not found` with what it searched, never an inference.
- **The scope decision is written from markdownifico's three jobs**: a parser, a linter and an HTML renderer, with HTML in the first release because the CommonMark spec's own test runner measures conformance on it. Each feature in the three lists names the columns that have it and the reason for its list.
- **The clock starts at this plan's commit.** Past one day, the work stops and the doc is written with the cells gathered so far, the missing ones marked as such.
